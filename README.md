# OutlookTrayKeeper — [X] сворачивает Outlook в трей

Маленькая утилита для **классического** Microsoft Outlook (outlook.exe — Office 2016/2019/2021/2024/365, «классический» клиент):
нажатие на крестик **[X]** или **Alt+F4** **сворачивает окно Outlook в область уведомлений** (трей) вместо полного закрытия.

## Что делает утилита

1. **Отключает команду закрытия** главного окна Outlook: кнопка [X] становится серой, «случайно» закрыть Outlook больше не получится — не сработает ни клик по [X], ни Alt+F4, ни «Закрыть окно» в контекстном меню панели задач.
2. **Превращает клик по [X] и Alt+F4 в свёртывание**: окно прячется к значку Outlook в области уведомлений, почта продолжает приходить.
3. **Включает штатную настройку Outlook** «Скрыть при свертывании» (параметр реестра `MinToTray`) — то же самое, что галка в меню значка Outlook, — чтобы свёрнутое окно уходило именно в трей, а не на панель задач.
4. **Прописывается в автозагрузку** текущего пользователя (отключается в меню значка утилиты).

Настоящий выход из Outlook по-прежнему доступен: меню Outlook **«Файл → Выход»** или **«Завершить Outlook…»** в меню значка утилиты.

## Требования

- Windows 10/11 (подойдёт и 8.1/7 с установленным .NET Framework 4.x);
- классический Outlook: 2016 / 2019 / 2021 / 2024 / Microsoft 365 («Использовать классический Outlook»);
- .NET Framework 4.x — уже есть в Windows 10/11 «из коробки»;
- права обычного пользователя. Исключение: если сам Outlook запущен **от имени администратора**, утилиту тоже нужно запускать от администратора, иначе Windows не позволит управлять его окном.

## Сборка (около 10 секунд)

1. Скопируйте папку `OutlookTrayKeeper` в постоянное место, например `C:\Tools\OutlookTrayKeeper`. Утилита прописывает путь к exe в автозагрузку — после пересборки в новом месте просто один раз заново запустите exe (путь обновится сам).
2. Дважды щёлкните **`build.bat`**. Он соберёт `OutlookTrayKeeper.exe` штатным компилятором Windows (csc.exe из .NET Framework). Ничего скачивать не нужно. Сборка «на месте» не помечается как файл из интернета, поэтому SmartScreen не появляется.
3. Запустите **`OutlookTrayKeeper.exe`** — в области уведомлений появится значок-конверт и всплывёт подсказка.

## Меню значка (правый щелчок по конверту)

| Пункт | Действие |
|---|---|
| Показать Outlook / Запустить Outlook | вернуть окно из трея или запустить Outlook |
| Свернуть Outlook в трей | свернуть окно прямо сейчас |
| Завершить Outlook… | настоящий выход из Outlook (с подтверждением) |
| Разрешить закрытие (снять перехват) | временно вернуть обычное поведение [X] и Alt+F4 |
| Автозапуск при входе в Windows | включить/выключить автозагрузку утилиты |
| Открыть журнал диагностики | открыть файл %TEMP%\OutlookTrayKeeper.log в Блокноте (нужен при разборе проблем) |
| О программе… | краткая справка |
| Выход из OutlookTrayKeeper… | остановить утилиту (кнопка [X] снова станет обычной) |

Двойной щелчок по значку утилиты = «Показать Outlook». Вернуть окно можно и обычным щелчком по родному значку Outlook в трее.

## Как это работает (кратко)

- Кнопка [X] гасится через системное меню окна Outlook (`EnableMenuItem`/`SC_CLOSE`) — тот же механизм, что у окон-инсталляторов с серым крестиком.
- Клик по [X] и нажатие Alt+F4 перехватываются глобальными низкоуровневыми хуками мыши и клавиатуры (`WH_MOUSE_LL` / `WH_KEYBOARD_LL`) и заменяются командой «свернуть». Клик по [X] относится к окну **под курсором** (`WindowFromPoint`), а не к переднему окну — так перехватывается и клик по [X] неактивного окна Outlook. Сам клик распознаётся двумя независимыми проверками: хит-тестом окна (`WM_NCHITTEST` → `HTCLOSE`) и — если окно занято и не отвечает, либо отвечает `HTCAPTION` на всю полосу кнопок (так делает реальный классический Outlook) — правой третью полосы кнопок заголовка по данным DWM (`DwmGetWindowAttribute`), для которой ответ от окна не нужен. DLL никуда не внедряется, весь остальной ввод проходит без изменений.
- Перехватывается **только главное окно** Outlook. У окон писем (открытых отдельно) тот же класс окна `rctrl_renwnd32`, поэтому главное окно определяется по содержимому: заголовок заканчивается на «- Outlook» и внутри есть список сообщений (класс `SUPERGRID`). Окна писем, диалоги и напоминания не затрагиваются.
- Свернутое окно прячется в трей силами самого Outlook (включённая утилитой штатная опция «Скрыть при свертывании»).
- Все изменения обратимы: при выходе утилита возвращает кнопке [X] обычный вид.

## Полное удаление

1. Меню значка утилиты → «Выход из OutlookTrayKeeper…» (кнопка [X] Outlook вернётся в нормальный вид).
2. Удалите папку с программой (удалите и запись в автозагрузке, если она осталась: Диспетчер задач → вкладка «Автозагрузка»).
3. Если хотите, чтобы свёрнутое Outlook снова оставалось на панели задач: правый щелчок по значку Outlook в трее → снимите галку **«Скрыть при свертывании»** (или удалите параметр `MinToTray` в разделе `HKEY_CURRENT_USER\Software\Microsoft\Office\16.0\Outlook\Preferences`).

## Известные особенности (FAQ)

- **[X] выглядит серым** — так задумано: кнопка больше не закрывает программу, а сворачивает её в трей.
- **Outlook сворачивается на панель задач, а не прячется в трей** — перезапустите Outlook один раз (опция «Скрыть при свертывании» применяется при старте Outlook) либо включите эту галку вручную в меню значка Outlook.
- **Антивирус предупреждает** — утилита использует штатный механизм Windows (глобальные хуки ввода), который любят мониторить антивирусы. Перехватывается только клик по [X] и Alt+F4; весь остальной ввод проходит насквозь. Исходный код полностью открыт в `OutlookTrayKeeper.cs`.
- **Пункт «Файл → Выход» по-прежнему закрывает Outlook** — это осознанно: способ выйти есть всегда, даже без утилиты под рукой.
- **«Новый Outlook» (веб-версия)** не поддерживается — у него собственная логика закрытия; утилита рассчитана на классический outlook.exe.
- Диалоги и всплывающие окна Outlook (напоминания и т.п.), а также письма, открытые в отдельных окнах, не затрагиваются — перехватывается только главное окно (в версиях до 1.5 серым становился и [X] окон писем).
- **Клик по [X] ничего не делает** — сначала убедитесь, что работает новая версия: правый щелчок по значку утилиты → «О программе…» — должно быть **1.5** (если там 1.0–1.4, пересборка не применилась: выйдите из утилиты и запустите `build.bat` заново; до 1.3 клик по [X] неактивного окна игнорировался, до 1.4 клик по [X] реального Outlook не распознавался вовсе, до 1.5 перехват захватывал и окна писем). Проверьте, что в меню не стоит галка «Разрешить закрытие». Если версия 1.5, а клик по-прежнему игнорируется — откройте в меню значка «Открыть журнал диагностики», щёлкните [X] и приложите последние строки журнала к сообщению: там зафиксировано, что именно увидел перехватчик (координаты клика, результат хит-теста, решение).

## История версий

**1.5 (текущая)** — исправлено: перехват и «серый [X]» распространялись на **дочерние окна** Outlook — письма, открытые в отдельных окнах: их кнопка [X] тоже становилась серой, и закрыть письмо было нельзя. Причина: у главного окна Outlook и у окон писем один и тот же класс окна (`rctrl_renwnd32`), и утилита их не различала. Теперь обрабатывается только главное окно — оно определяется по двум независимым признакам: заголовку, заканчивающемуся именем приложения («Папка - Outlook»; у окна письма в заголовке тема письма), и наличию списка сообщений — дочернего контрола класса `SUPERGRID`. Окна писем утилита не трогает; если версия до 1.5 уже успела погасить в них кнопку, утилита вернёт ей активный вид автоматически (в журнале появится строка «окно письма: кнопка [X] была погашена — возвращён активный вид»).

**1.4** — исправлен главный случай: клик по [X] **реального** классического Outlook не перехватывался вообще — окно не сворачивалось, серый [X] просто ничего не делал. Причина: настоящий Outlook отвечает на хит-тест `WM_NCHITTEST` кодом `HTCAPTION` по всей полосе своих кнопок заголовка (включая [X]), поэтому основная проверка «hittest = HTCLOSE» на нём не срабатывала никогда — в журнале это видно по кликам точно в [X] с `hittest=2`. Теперь правая треть полосы кнопок заголовка по данным DWM (`DwmGetWindowAttribute`) проверяется и в этом случае, а не только когда окно занято и не отвечает на хит-тест. Кнопки «свернуть»/«развернуть» не затронуты: на обычных окнах хит-тест честно отвечает `HTMINBUTTON`/`HTMAXBUTTON`, и новая проверка не включается. Проверено автотестом на заглушке, воспроизводящей поведение реального Outlook (все кнопки заголовка отвечают HTCAPTION): клики по [X] активного, неактивного и развёрнутого окна и Alt+F4 сворачивают; на обычной заглушке прежние проверки также проходят.

**1.3** — исправлено ещё два случая, когда клик по [X] ничего не делал.

1. Перехват сравнивал координаты клика только с **передним** окном, а активация происходит уже *после* нажатия кнопки. Поэтому клик по [X] **неактивного** окна Outlook (например, когда поверх открыт браузер, и вы щёлкаете крестик «через» него) не рассматривался вовсе: клик доходил до Outlook, но серый [X] просто ничего не делал. Теперь перехват определяет окно **под курсором** (`WindowFromPoint` + `GetAncestor(GA_ROOT)`).
2. «Запасная проверка по прямоугольнику кнопки закрытия», добавленная в 1.2, не работала никогда. Прямоугольники кнопок возвращает структура `TITLEBARINFOEX` (сообщение `WM_GETTITLEBARINFOEX`), а не `GetTitleBarInfo`/`TITLEBARINFO`, в котором этого массива нет; из-за лишнего поля объявленная структура не совпадала по размеру с настоящей, и проверка всегда отвечала «нет» (вдобавок на Windows 11 реальные данные `TITLEBARINFOEX` не соответствуют расположению кнопок). Теперь запасная проверка — полоса кнопок заголовка из данных оконного менеджера DWM (`DwmGetWindowAttribute` / `DWMWA_CAPTION_BUTTON_BOUNDS`): для неё не нужен ответ самого окна, поэтому она срабатывает, даже когда Outlook занят и не отвечает на хит-тест.

Исправление проверено автоматическим тестом на окне-заглушке (процесс OUTLOOK.exe с главным окном класса `rctrl_renwnd32`): клик по [X] активного окна, клик по [X] неактивного окна и Alt+F4 сворачивают окно; клик по кнопке «развернуть» не затрагивается.

**1.2** — исправлено нераспознавание клика по [X] на экранах с масштабированием (125%, 150% и т.п.). Причина: у exe не было манифеста, процесс оставался DPI-unaware, Windows масштабировала для него координаты, и точка клика из хука не совпадала с координатами окна Outlook (Alt+F4 работал, потому что координаты ему не нужны). Изменения: (1) при старте включается DPI-awareness — per-monitor v2 с поэтапным откатом к старым API; (2) добавлена запасная проверка клика по прямоугольнику кнопки закрытия (в 1.3 выяснилось, что она не работала, и была заменена на проверку по данным DWM); (3) добавлен журнал диагностики (меню значка → «Открыть журнал диагностики», файл `%TEMP%\OutlookTrayKeeper.log`), в котором фиксируются все клики по заголовку Outlook и решения перехватчика.

**1.1** — исправлен перехват клика по [X]: в v1.0 код попадания в кнопку (результат `WM_NCHITTEST`) брался из возвращаемого значения `SendMessageTimeout`, тогда как он приходит в отдельном out-параметре. Из-за этого клик по [X] ничего не делал, хотя Alt+F4 и пункт меню «Свернуть Outlook в трей» работали.

Порядок обновления уже собранной копии:

1. Правый щелчок по значку утилиты → **«Выход из OutlookTrayKeeper…»** — утилита вернёт [X] обычный вид и освободит exe-файл.
2. Скопируйте из нового архива файлы `OutlookTrayKeeper.cs` и `README.md` поверх старых.
3. Запустите **`build.bat`** — он пересоберёт `OutlookTrayKeeper.exe` с исправлением.
4. Запустите `OutlookTrayKeeper.exe` и проверьте: в «О программе…» указана версия **1.5**, клик по [X] сворачивает окно в трей (в том числе когда окно Outlook неактивно), а письмо в отдельном окне закрывается своим [X] как обычно.
